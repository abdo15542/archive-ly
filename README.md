# أرشيف | ARCHIVE LY

نظام عربي لإدارة وأرشفة الوثائق إلكترونياً، بواجهة RTL وواجهة API وقاعدة PostgreSQL وعامل OCR منفصل.

## المكونات
- `apps/api`: Express API، مصادقة JWT، إدارة الوثائق والتصنيفات.
- `apps/web`: React + Vite، لوحة عربية لإدارة الوثائق.
- `apps/api/src/workers/ocr.js`: عامل OCR غير متزامن للعربية والإنجليزية.
- `/api/admin/users`: إدارة حسابات المستخدمين وأدوارهم وحالة تفعيلهم للمسؤول.
- `/api/admin/audit-logs`: استعراض سجل العمليات مع مرشحات أساسية.
- PostgreSQL: بيانات الوثائق والمستخدمين وطابور المهام وسجل التدقيق.
- Docker: تشغيل قاعدة البيانات والخادم والعامل مع مجلد ملفات دائم.

## التشغيل المحلي باستخدام Docker
1. أنشئ قيمة سرية طويلة لـ JWT:
   `export JWT_SECRET="$(openssl rand -hex 32)"`
2. شغّل الخدمات:
   `docker compose up --build -d`
3. تحقق من الخدمة:
   `curl http://localhost:4000/health`
4. افتح الواجهة أثناء التطوير:
   `npm install && npm run dev:web`
   ثم اضبط `VITE_API_URL=http://localhost:4000` عند الحاجة.

## التشغيل دون Docker
- Node.js 20+ وPostgreSQL 15+.
- انسخ `.env.example` إلى `.env`، واضبط `DATABASE_URL` و`JWT_SECRET`.
- ثبّت Tesseract مع `ara` و`eng` وPoppler على الجهاز الذي سيشغّل عامل OCR.
- نفّذ `npm install` ثم `npm run db:migrate`.
- شغّل API: `npm run dev`.
- شغّل عامل OCR في عملية منفصلة: `npm run worker:ocr`.
- شغّل الواجهة: `npm run dev:web`.

## أول استخدام
أنشئ حساب المسؤول الأول من شاشة الدخول. التسجيل الأول فقط متاح؛ بعده يُغلق التسجيل العام. يمكن للمسؤول إنشاء حسابات إضافية عبر أدوات الإدارة التي ستُستكمل في المرحلة التالية.

## حدود الإصدار الحالي
- OCR للصور وPDF، مع استخراج النص الرقمي أولاً وتحويل PDF الممسوح لأول 15 صفحة افتراضياً.
- OCR لا يضمن دقة 100%، وتختلف النتيجة حسب جودة المسح.
- واجهات إدارة المستخدمين وسجل العمليات متاحة للمسؤول من لوحة التحكم، وإدارة التصنيفات متاحة للمسؤول وأمين الأرشيف.
- عارض PDF داخل تفاصيل الوثيقة، مع تحميل الملف عبر جلسة مصادق عليها والتنقل بين الصفحات والتكبير.
- لم يُعلن هذا الإصدار كنسخة إنتاجية معتمدة قبل اجتياز اختبارات التكامل والنشر والتحقق الأمني.


## النسخ الاحتياطي والاستعادة

تتطلب الأوامر وجود PostgreSQL client وأداة `tar` (مضمّنتان في صورة Docker الخاصة بالمشروع).

- أنشئ نسخة كاملة من قاعدة البيانات والملفات: `npm --workspace apps/api run backup`.
- حدد مسار النسخ بواسطة `BACKUP_DIR`، ومجلد الملفات بواسطة `UPLOAD_DIR`.
- استعد نسخة: `npm --workspace apps/api run restore -- /absolute/path/to/archive-ly-backup-<timestamp>.tar.gz`.
- عبر Docker Compose: نفّذ `docker compose --profile tools run --rm backup` لإنشاء النسخة داخل volume مستقل اسمه `archive_backups`.
- قبل الاستعادة يتحقق النظام من بصمات SHA-256 لملف قاعدة البيانات وأرشيف الملفات. الاستعادة تستبدل محتويات قاعدة البيانات الحالية؛ خذ نسخة احتياطية منفصلة قبل تنفيذها. عند استخدام Docker، شغّل خدمة backup بأمر restore مع تمرير مسار النسخة تحت `/backups`.
- احتفظ بالنسخ خارج مجلد الرفع، وعلى وسيط تخزين منفصل أو مشفر. لا تضع النسخ الاحتياطية في مجلد الويب العام.

> ملاحظة: النسخ الاحتياطي لا يُجدول تلقائياً في هذه المرحلة. يجب تشغيل أمر backup دورياً عبر cron أو منصة الاستضافة ومراقبة نجاحه.
