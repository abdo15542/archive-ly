# محرك OCR العربي

يعتمد النظام على Tesseract مع حزمتي اللغة العربية والإنجليزية، وعلى Poppler لاستخراج النص من PDF الرقمي وتحويل صفحات PDF الممسوحة إلى صور عند الحاجة.

## دورة المعالجة
1. يرفع أمين الأرشيف وثيقة PDF أو صورة مدعومة.
2. يتحقق الخادم من ترويسة الملف الفعلية ويحسب SHA-256.
3. ينشئ سجل مهمة في `ocr_jobs` ويعيد حالة `queued`.
4. عامل OCR مستقل يحجز المهمة باستخدام PostgreSQL `SKIP LOCKED` حتى يمكن تشغيل أكثر من عامل.
5. يستخرج النص الرقمي من PDF أولاً؛ إذا لم يوجد نص كافٍ يحول أول عدد محدد من الصفحات إلى صور ويشغل OCR باللغة `ara+eng`.
6. يحفظ النص وحالة المعالجة في سجل الوثيقة، ويصبح النص قابلاً للبحث من واجهة الوثائق.

## حدود التشغيل
- PDF الممسوح: تتم معالجة أول 15 صفحة افتراضياً؛ يمكن تغيير `OCR_MAX_PDF_PAGES`.
- تحتاج الصور الواضحة والدقة الجيدة إلى نتائج أفضل. OCR ليس ضماناً لصحة كل حرف.
- العامل يحتاج إلى Tesseract وملفات اللغة وPoppler. صورة Docker في المستودع تجهز هذه المتطلبات.
- في الإنتاج يجب تشغيل API والعامل على خدمة/حاوية واحدة بمجلد رفع دائم مشترك، أو نقل الملفات إلى تخزين كائنات مشترك.
- لا ترفع ملفات حساسة إلى بيئة عامة دون تهيئة صلاحيات وتشفير ونسخ احتياطي مناسب.
