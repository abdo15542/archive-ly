# أرشيف | ARCHIVE LY

نظام عربي لإدارة وأرشفة الوثائق إلكترونياً، بواجهة RTL وواجهة API وقاعدة PostgreSQL وعامل OCR منفصل.

## المكونات
- `apps/api`: Express API، مصادقة JWT، إدارة الوثائق والتصنيفات.
- `apps/web`: React + Vite، لوحة عربية لإدارة الوثائق.
- `apps/api/src/workers/ocr.js`: عامل OCR غير متزامن للعربية والإنجليزية.
- `/api/admin/users`: إدارة حسابات المستخدمين وأدوارهم وحالة تفعيلهم للمسؤول.
- `/api/admin/audit-logs`: استعراض سجل العمليات مع مرشحات أساسية.
- `/api/admin/ocr/queue`: إحصاءات طابور OCR وقائمة المهام مع تصفية الحالة والترقيم، للمسؤول فقط.
- `/api/admin/ocr/jobs/:id/retry`: إعادة إدراج المهمة الفاشلة في الطابور مع تسجيل العملية في سجل التدقيق.
- `/api/admin/ocr/workers`: حالة عمّال OCR وآخر نبضة ووقت بدء التشغيل والتوقف؛ تُعرض حالة الانقطاع في لوحة المسؤول إذا تجاوزت النبضة 45 ثانية.
- PostgreSQL: بيانات الوثائق والمستخدمين وطابور المهام وسجل التدقيق.
- Docker: تشغيل قاعدة البيانات والخادم والعامل مع مجلد ملفات دائم.

## التشغيل المحلي باستخدام Docker
1. أنشئ قيمة سرية طويلة لـ JWT:
   `export JWT_SECRET="$(openssl rand -hex 32)"`
2. شغّل الخدمات:
   `docker compose up --build -d`
3. تحقق من الخدمة:
   `curl http://localhost:4000/health`
4. افتح الواجهة أثناء التطوير:
   `npm install && npm run dev:web`
   ثم اضبط `VITE_API_URL=http://localhost:4000` عند الحاجة.

## التشغيل دون Docker
- Node.js 20+ وPostgreSQL 15+.
- انسخ `.env.example` إلى `.env`، واضبط `DATABASE_URL` و`JWT_SECRET`.
- ثبّت Tesseract مع `ara` و`eng` وPoppler على الجهاز الذي سيشغّل عامل OCR.
- نفّذ `npm install` ثم `npm run db:migrate`.
- شغّل API: `npm run dev`.
- شغّل عامل OCR في عملية منفصلة: `npm run worker:ocr`.
- شغّل الواجهة: `npm run dev:web`.

## أول استخدام
أنشئ حساب المسؤول الأول من شاشة الدخول. التسجيل الأول فقط متاح؛ بعده يُغلق التسجيل العام. يمكن للمسؤول إنشاء حسابات إضافية عبر أدوات الإدارة.

## حدود الإصدار الحالي
- OCR للصور وPDF، مع استخراج النص الرقمي أولاً وتحويل PDF الممسوح لأول 15 صفحة افتراضياً.
- OCR لا يضمن دقة 100%، وتختلف النتيجة حسب جودة المسح.
- واجهات إدارة المستخدمين وسجل العمليات متاحة للمسؤول من لوحة التحكم، وإدارة التصنيفات متاحة للمسؤول وأمين الأرشيف.
- عارض PDF داخل تفاصيل الوثيقة، مع تحميل الملف عبر جلسة مصادق عليها والتنقل بين الصفحات والتكبير.
- لم يُعلن هذا الإصدار كنسخة إنتاجية معتمدة قبل اجتياز اختبارات التكامل والنشر والتحقق الأمني.

## النسخ الاحتياطي والاستعادة

تتطلب الأوامر وجود PostgreSQL client وأداة `tar` (مضمّنتان في صورة Docker الخاصة بالمشروع).

- نسخة يدوية: `docker compose --profile tools run --rm backup`.
- استعادة نسخة: `docker compose --profile tools run --rm --entrypoint npm backup --workspace apps/api run restore -- /backups/اسم-النسخة.tar.gz`.
- تحقق النظام من SHA-256 قبل الاستعادة. الاستعادة تستبدل قاعدة البيانات الحالية؛ خذ نسخة منفصلة أولاً.
- النسخ تحفظ في volume اسمه `archive_backups`، ويجب تصديرها دورياً إلى تخزين خارجي منفصل أو مشفر.

### تشغيل النسخ التلقائي
1. ابدأ الخدمات الأساسية: `docker compose up -d --build`.
2. شغّل المجدول: `docker compose --profile tools up -d backup-scheduler`.
3. ينفذ المجدول نسخة فور بدء الخدمة، ثم يكررها كل 24 ساعة افتراضياً.
4. يحتفظ بآخر 30 يوماً ويحذف فقط الملفات العادية التي تطابق النمط `archive-ly-backup-*.tar.gz`.
5. راقب السجل: `docker compose logs -f backup-scheduler`.
6. أوقف المجدول: `docker compose stop backup-scheduler`.

يمكن ضبط `BACKUP_INTERVAL_HOURS` (من 1 إلى 8760) و`BACKUP_RETENTION_DAYS` (من 1 إلى 3650) في ملف البيئة. إذا فشل النسخ، يسجل المجدول الخطأ ويعيد المحاولة في الدورة التالية. لا تُعد النسخ داخل Docker وحدها خطة تعافٍ كافية؛ صدّرها خارج الخادم واختبر الاستعادة دورياً.

## الاختبارات
